# 第 12 版「切割訓練」說明 + v8 對照 + 合併新資料重訓步驟

這份文件用來補齊你對 v12 訓練流程的理解，並對照第 8 版，最後給出「把新資料
（AVNFH）合併進來重新訓練」的實際操作步驟。

---

## 0. 一句話總覽

- **第 8 版**：憑經驗**手動挑一條**階層（先分 stage4 → 再分 stage1 → 最後分 2 vs 3），
  每個節點**手動指定 backbone**。
- **第 12 版**：把 4 分類**拆成 10 個二元 cut**，每個 cut 自動跑 5-fold × 7 個 backbone，
  用 **OOF（out-of-fold）**成績自動選拔，再**自動搜尋 5 種階層**並用 OOF 選最好那條，
  最後多一個**學習型 combiner**。**選拔全程不碰 test set**，所以分數誠實、能寫進論文。

> 白話：v8 是「老師憑經驗選一條路」，v12 是「把所有路都試過、用不作弊的方式選出最好的那條」。

---

## 1. 什麼是「切割 (cut)」

Ficat 有 4 個 stage。v12 不直接做 4 分類，而是拆成 10 個**二元問題**（見
`src/renai/cuts_registry.py`）：

| cut | label 0 | label 1 |
| --- | --- | --- |
| `1_vs_234` | 1 | 2,3,4 |
| `12_vs_34` | 1,2 | 3,4 |
| `123_vs_4` | 1,2,3 | 4 |
| `2_vs_34` | 2 | 3,4 |
| `23_vs_4` | 2,3 | 4 |
| `1_vs_23` | 1 | 2,3 |
| `12_vs_3` | 1,2 | 3 |
| `2_vs_3` | 2 | 3 |
| `1_vs_2` | 1 | 2 |
| `3_vs_4` | 3 | 4 |

一條「階層 (topology)」只會用其中 **3 個 cut**，把樣本一路分到 stage 1/2/3/4。

---

## 2. 每個 cut 怎麼訓練（這就是你問的「切割訓練」）

對每個 cut（`scripts/04_train_all_cuts.py` → `src/renai/cv.py`）：

1. 固定的 80/20 outer split（`outputs/splits/outer_split.json`），test 20% **鎖起來不動**。
2. 在 train_val 80% 上做 **5-fold 分層 CV**。
3. 每個 fold 訓練 **7 個 backbone**：
   `efficientnet_b0/b1, resnet50, convnext_tiny/small, densenet121/169`。
4. 訓練設定：class-weighted cross-entropy（處理類別不平衡）＋ AdamW weight decay
   ＋ early stopping；增強是 affine + 亮度/對比 jitter，**故意不做水平翻轉**
   （因為右髖已經翻成左髖方向了，翻了會把內外側搞反）。
5. 所以每個 cut 會訓練 `5 folds × 7 backbones = 35` 個 checkpoint。

**但集成只用「每個 fold 表現最好的那個 backbone」**，也就是 5 個 checkpoint。
選拔依據是每個 fold 的 validation macro-F1（`ensemble.py` 讀 `val_metrics.json`）。

---

## 3. OOF 是什麼、為什麼重要

OOF = out-of-fold。某張 train_val 影像若落在 fold 2 的 validation，它的 OOF 預測就
**只由 fold 2 的模型產生**（那個模型訓練時沒看過它）。這樣的預測接近「沒看過資料」
的真實表現。

v12 的核心原則：**用 OOF 成績做所有選拔，test set 只在最後回報一次。** 這就是它比
v8 誠實的地方。

---

## 4. 兩種集成 + topology 搜尋

- 每個 cut 比較 `fold_voting`（5 個 fold winner 的 softmax 平均）與 `stacking`
  （再套一層 LogReg），用 OOF macro-F1 選，寫進 `outputs/cuts/<cut>/ensemble/winner.json`。
- `scripts/06_search_hierarchy.py` 對 5 種 topology 都算 OOF 4-class macro-F1，
  **選 OOF 最高的**（不是 test 最高，避免洩漏），寫進 `best_topology.json`。
  目前選到的是 **T1 `((1,2),(3,4))`**。

| Topology | 結構 | 用到的 cut |
| --- | --- | --- |
| T1 | ((1,2),(3,4)) | 12_vs_34, 1_vs_2, 3_vs_4 |
| T2 | (1,(2,(3,4))) | 1_vs_234, 2_vs_34, 3_vs_4 |
| T3 | (1,((2,3),4)) | 1_vs_234, 23_vs_4, 2_vs_3 |
| T4 | ((1,(2,3)),4) | 123_vs_4, 1_vs_23, 2_vs_3 |
| T5 | (((1,2),3),4) | 123_vs_4, 12_vs_3, 1_vs_2 |

## 5. 學習型 combiner（v8 沒有）

`scripts/09_train_combiner.py`：把每個 cut 的 P(class=1) 當特徵，用一個 4-class 分類器
（LogReg / SVM / RandomForest / HistGB / XGBoost）直接學 4 分類，取代「一刀切錯就回不來」
的硬路由。`combiner[all]`（10 個 cut 當特徵）在**內部 test**上是最好的。

---

## 6. v8 ↔ v12 對照

| 面向 | 第 8 版 | 第 12 版 |
| --- | --- | --- |
| 階層 | **手動固定一條**：M1 stage4-vs-其他 → M2 stage1-vs-其他 → M3 stage2-vs-3 | **自動搜尋 5 種**，OOF 選最佳 |
| 對應關係 | v8 的那條 = **v12 的 T4** `((1,(2,3)),4)`（cut: 123_vs_4, 1_vs_23, 2_vs_3） | v12 涵蓋 T1~T5，含 T4 |
| backbone | 每個 model **手選固定**（M1/M3=DenseNet121、M2=3 個做 stacking） | 每個 cut 每個 fold **自動選 7 選 1** |
| 選拔依據 | 主要看 val / test | **只看 OOF**，test 只回報 |
| 集成 | M2 用 stacking | 每個 cut 自動比 voting vs stacking |
| 4-class 整合 | 硬邏輯串接 | 硬路由 **＋** 學習型 combiner |
| 不確定性 | 單一數字 | bootstrap 95% 信賴區間 |
| t-SNE / Grad-CAM / web app | 有 | 有（`10/12_tsne`、`gradcam.py`、`web_app/`） |

**結論：v12 是 v8 的超集。** v8 的 3 個手選模型（M1/M2/M3）對應的 cut
（`123_vs_4`、`1_vs_23`、`2_vs_3`）在 v12 都有訓練，而且 v12 還多訓練了另外 7 個 cut。
所以「補齊」不是把 v8 的東西搬過來——v12 已經全部涵蓋，只是把「手選」換成「自動＋誠實選拔」。

> 唯一 v8 有、v12 目前沒有主打的細節：v8 的 M2 明確用「3 個指定 backbone 做 stacking」。
> v12 的 stacking 是每個 cut 自動決定，目前 10 個 cut 都選了 fold_voting。如果你想在論文裡
> 重現 v8 的 M2 stacking 當對照組，可以之後再加，但這不是主線。

---

## 7. Step B：把新資料（AVNFH）合併進來重新訓練

> ⚠️ 這一步很久（10 cuts × 5 folds × 7 backbones）。確定要做再啟動。
> 先做過 Step A 外部驗證（`scripts/13_external_eval.py`）再決定。

### 7.1 合併資料（注意檔名撞名）

AVNFH 已經用 `scripts/01_prepare_stage_dataset.py --source-prefix A_` 裁好，放在
`stage_cls_avnfh/`，檔名是 `S{stage}_A_{L/R}{n}.jpg`，**和舊資料不會撞名**。合併做法：

```powershell
# 把 AVNFH 的裁切結果併進主資料集（A_ 前綴保證不覆蓋舊檔）
foreach ($n in 1..4) {
  Copy-Item "stage_cls_avnfh\stage_$n\*.jpg" "stage_cls_dataset\stage_$n\"
}
```

合併後每類張數會變成（舊 + 新）：
stage_1 = 49+49、stage_2 = 112+84、stage_3 = 60+22、stage_4 = 66+9。

### 7.2 重新產生 split（重要）

`outputs/splits/outer_split.json` 會被沿用。資料量變了以後**必須刪掉它**，讓程式
用新的資料重新切 80/20，否則新資料不會進 test：

```powershell
Remove-Item outputs\splits\outer_split.json -Force
```

> 若之後拿到「檔名→病人 ID」對照表，把它加進 `roi_all.csv` 的 `patient` 欄位，
> `data.py` 會自動改用病人層級切分（`StratifiedGroupKFold`），這是消除病患洩漏的正解。
> 在拿到之前，切分是影像層級，若 AVNFH 與舊資料有相同病患，數字仍可能略微樂觀。

### 7.3 建議保留一份乾淨外部 hold-out

不要把 AVNFH 全部丟進訓練。建議**保留一部分 AVNFH 當外部測試**（例如整個 stage 各留
一部分不合併），這樣還能繼續用 `13_external_eval.py` 得到「完全沒看過」的泛化數字。

### 7.4 重新訓練 + 重建報表

```powershell
conda activate unet_labeling
python scripts/04_train_all_cuts.py            # 很久：重訓 10 cuts
python scripts/05_build_ensemble.py            # 重建 OOF ensemble
python scripts/06_search_hierarchy.py          # 重選 topology
python scripts/08_report_ci.py                 # 重算信賴區間
python scripts/09_train_combiner.py            # 重訓 combiner
python scripts/07_update_web.py                # 更新 web app runtime
```

跑完再用 `13_external_eval.py` 對保留的外部 hold-out 驗證，比較「合併前 vs 合併後」的
外部泛化成績，就能誠實回答「加新資料到底有沒有幫助」。
