## 0. 先看這張「進化地圖」

```
第8版：手選一條階層 + 手選 backbone            （憑經驗）
  │
第12版(原)：10 個二元 cut → OOF 自動選 → 硬階層 / RandomForest combiner
  │          （自動、誠實選拔，但「不管期別順序」）
  │
本次升級：
  ① 序數模型 CORN            ← 把「1<2<3<4 有順序」寫進模型
  ② 類別加權                 ← 逼模型別忽略少數期別
  ③ 9 骨幹集成 + OOF 加權    ← 多個模型互補、投票
  ④ 合併 AVNFH 資料重訓       ← 資料變多
  ⑤ 病人層級切分 + AVNFH補ID  ← 消除「同一病人同時在 train/test」的洩漏
```

**一句話**：v12 原本是「把 4 分類拆成很多個各自獨立的是非題」；這次改成「**一個懂順序的模型**」，
再把**資料處理的誠實度**做到位（病人層級、補 ID、防洩漏）。

## 1. 為什麼「期別有順序」這件事很關鍵

Ficat 有 4 期，而且是**有輕重順序的**：1 → 2 → 3 → 4 越來越嚴重。

- **一般 4 分類**把它當成 4 個**不相干的盒子**（像分「貓/狗/鳥/魚」），完全不知道「3 夾在 2 和 4 中間」。
  → 後果：把 stage 3 猜成 stage 1（差 2 階，大錯）跟猜成 stage 2（差 1 階，小錯），對它來說「一樣錯」。
- 但醫學上，**把 stage 3 判成 stage 2（差一階）遠比判成 stage 1（差三階）輕微**。

所以我們要一個「知道順序」的模型，這就是 **序數（ordinal）模型**。

---

## 2. CORN 是什麼（重點，慢慢講）

### 2.1 舊 v12 的做法（10 個獨立是非題）
原本把 4 分類拆成 10 個二元 cut，例如 `12_vs_34`（是 1-2 期還是 3-4 期？）。
**每個 cut 是一個獨立訓練的 CNN**。問題有三個：
1. 10 個 CNN 各自從 ~230 張圖從頭學，**資料利用率差**（同樣的髖關節特徵學了 10 遍）。
2. 它們**互不知道對方**，機率會自相矛盾（例如某張圖 `P(≥3)=0.8` 卻 `P(≥2)=0.6`，但邏輯上「≥3」的機率不可能比「≥2」還高）。
3. 最後用 RandomForest 把 10 個機率**當成無序特徵**硬學，還是不懂順序。

### 2.2 CORN 的做法（一個模型，問 3 個「有序」的是非題）
CORN = **CO**nditional **R**ank regression for **N**eural networks（一種序數回歸法，2021 年提出）。

**核心概念**：不拆成 10 個獨立模型，而是用**一個共享的 CNN**，尾巴接 **3 個輸出**，同時回答 3 個**累積**問題：

| 輸出 | 問題 |
| --- | --- |
| 第 1 個 | 「這張是不是 **≥ stage 2**？」 |
| 第 2 個 | 「這張是不是 **≥ stage 3**？」 |
| 第 3 個 | 「這張是不是 **≥ stage 4**？」 |

**怎麼得到最終期別？數有幾個「是」再 +1**：
```
≥2? 是   ≥3? 是   ≥4? 否   →  數到 2 個「是」  →  stage 3
≥2? 是   ≥3? 否   ≥4? 否   →  數到 1 個「是」  →  stage 2
≥2? 否                      →  數到 0 個「是」  →  stage 1
```
（這叫 rank-count 解碼。）

**CORN 的三個好處，剛好治好 2.1 的三個病**：
1. **共享一個 CNN** → 髖關節特徵只學一遍，小資料上學得更好。
2. **數學上保證順序一致**：CORN 用「鏈式相乘」算累積機率，天生保證 `P(≥2) ≥ P(≥3) ≥ P(≥4)`，不會自相矛盾。
3. **用序數損失訓練** → 它知道「差一階」和「差三階」該受不同懲罰。

> 白話比喻：舊做法是「請 10 個各自為政的專科醫師，每人只回答一個是非題，最後找個人硬湊」；
> CORN 是「訓練**一位**醫師，一次做出『至少 2 期？至少 3 期？至少 4 期？』的連貫判斷」。

### 2.3 類別加權（class weighting）
資料很不平均（stage 2 有 196 張，stage 4 只有 75 張）。不加權的話，模型會偷懶：反正多猜 stage 2 準確率就不差。
**加權 = 告訴模型「猜錯少數期別要扣更多分」**，逼它認真看 stage 1、4。
（我還加了可選的 `--stage3-weight`，專門加重 stage 3，但實測發現它會「劫富濟貧」，見主文件 §0.3。）

### 2.4 集成（ensemble）
不只訓練一個 CNN，而是訓練好幾種不同架構（EfficientNet、ConvNeXt、DenseNet、ResNet…），
把它們的答案**平均**。不同架構會犯不同的錯，平均後互相抵銷 → 更穩。
我還用 **OOF 加權**：表現好的骨幹投票權重高、表現差的權重低。

## 3. 資料是怎麼處理的

### 3.1 從原始 X 光到可訓練的圖
```
骨盆 X 光 → YOLO 自動框出髖關節 ROI → 裁切 → 右髖翻成左髖方向（統一） → 存成 stage_1..4 資料夾
```
（右髖翻成左髖是為了統一方向，所以訓練時**故意不做水平翻轉**，否則會把內外側搞反。）

### 3.2 「切割 (cut)」是什麼
把 4 期**重新貼標成二元**。例如 cut `12_vs_34`：把 stage 1、2 都標成「0」，stage 3、4 標成「1」。
v12 原本靠這些 cut 組成階層。**CORN 之後其實不再需要這些 cut**（CORN 直接一個模型學 4 期），
但 cut 的邏輯還在（累積 cut `1_vs_234 / 12_vs_34 / 123_vs_4` 正好就是 CORN 的 3 個累積問題）。

### 3.3 資料怎麼切成 train / test（很重要）
- **外層 80/20**：80% 拿來訓練+驗證，20% **鎖起來當 test**（最後才看一次）。
- **內層 5-fold CV**：把 80% 再切 5 份，輪流當驗證，得到 **OOF（out-of-fold）預測**——
  每張圖的預測，都來自**一個沒看過它的模型**，所以接近「真實沒看過」的表現。
- **選模型只看 OOF，test 只回報一次** → 不作弊、能寫進論文。

### 3.4 合併 AVNFH（資料變多）
原本 287 張（舊資料）+ AVNFH 164 張 = **451 張**。更多資料通常 = 更好的準確度。
（放在 `stage_cls_merged/`，原始資料夾沒動。）

### 3.5 病人層級切分 + 補 AVNFH 病人 ID（這次最關鍵的誠實性升級）

**問題**：同一個病人可能有**多張** X 光（甚至不同期別各一張）。如果切分是「**按影像**」隨機切，
同一個病人的圖可能**同時落在 train 和 test**。這樣模型可能是「**認得這個病人**」而不是「看懂這個病」，
分數會虛高——這叫**病人洩漏 (patient leakage)**。

**解法**：改成「**按病人**」切分（`GroupShuffleSplit`）——同一病人的所有圖**綁在一起**，
要嘛全在 train、要嘛全在 test，絕不跨越。

**但要按病人切，得先知道每張圖是哪個病人**：
- **舊資料**：之前你用 OCR（`表格製作1.ipynb`）從 X 光角落讀出病人 ID，95% 有。
- **AVNFH**：本來沒有 ID。這次我用 **easyocr** 讀 AVNFH 角落的 `PID` 文字，**163/164（99%）補上 ID**。
- **驚人發現**：AVNFH 其實只有 **30 位病人**（不是 164！平均每人 5.4 張），而且 **8 位病人**
  同時出現在舊資料和 AVNFH 兩批、共 **64 張圖**——這些之前會**跨批次洩漏**。補上 ID 後才抓得掉。

**結果**：病人對照表從「259 個假群組」收斂成 **118 個真實病人群組（97% 覆蓋）**，切分才真正乾淨。

## 4. 為什麼「防洩漏後分數變低」是好事

補完病人 ID、完全防漏之後，數字從「看起來漂亮的 0.79」掉到「誠實的 0.66」（準確度）。
**這不是變爛，是把之前虛報的水分擠掉了。** 之前 0.79 有一部分是「模型認得病人」灌出來的。

而且要注意：我們資料只有 ~103 位病人，**單次切一份 test（88 張）本身就很吵**——
stage 3 只有 16 張，一次抽樣就能讓它的成績大起大落。所以**主要看「交叉驗證的 OOF」**（用全部 363 張、
每張由沒訓練過它的模型預測），單次 test 只當次要參考。

**最終誠實成績（完全防漏、OOF）：QWK 0.760、準確度 0.658、macro-F1 0.635。**
QWK 0.760 仍**遠高於人類醫師之間的一致性 κ 0.39–0.46**——這是最強的賣點。
